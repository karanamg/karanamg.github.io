      How the 3-way match works

      A vendor invoice is only paid when it agrees with what was ordered (purchase order) and what was actually received (goods receipt). For every invoice line the Boomi process checks:

      Flow

      BrowserUpload PDF, watch the run, dashboard
      →
      Node gatewayReads the PDF text (pdf.js) and builds the invoice JSON. Holds the Boomi credentials.
      →
      Boomi API Service3WM Invoice Match API
      POST /ws/rest/threeway/v1/match
      [SUB] 3WM Get Purchase OrderMock ERP purchase orders → split → keep the PO named on the invoice
      [SUB] 3WM Get Goods ReceiptsMock WMS receipts → split → keep receipts for the PO → combine
      3-way match engineCompares quantity, unit price and line value with tolerances
      DecisionApprove for payment, or route to the AP exception queue

      Boomi folder Companion/ThreeWayMatch. The two mock subprocesses are the swap-out points for real ERP (for example SAP or Oracle) and warehouse connectors.
